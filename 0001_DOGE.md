# Digital Octal Graphical Emissive (DOGE) Color Specification

> v1.0.0 - 20260730
>
> Pure 3 bit RGB color palette for high contrast emissive displays

## 1. Scope

This specification defines a pure 3 bit RGB color palette consisting of exactly eight colors. It is intended for high contrast graphical user interfaces, terminal emulators, and emissive displays (OLED and similar) where maximum channel purity is desired, especially for users with eyes sensitive to older LCD style light bleed.

The palette is a deliberate pure realization of the classic 3 bit RGB model that underlies the eight named colors of ECMA-48 / ISO/IEC 6429. Unlike those standards, which define only color names, this specification fixes the exact 24 bit sRGB values.

### 1.1 Status of this document

1. This document is normative for the DOGE palette, quantization, and related mapping requirements stated herein.
2. Versioning of this document SHALL follow [0000_spec.md](0000_spec.md) (the Surmount spec spec).

## 3. Definitions

### 3.1 DOGE

Digital Octal Graphical Emissive. The full name of this palette.

### 3.2 RGBCMYKW

The ordered set of the eight pure colors: Red, Green, Blue, Cyan, Magenta, Yellow, Black, White.

### 3.3 Pure 3 bit RGB

A color model in which each of the red, green, and blue channels is restricted to the extreme values 0 or 255 (1 bit per channel). The resulting eight combinations are the only permitted colors. No grayscale colors or other shades are permitted, for reasons including efficiency on more limited experimental hardware stacks, and the understanding that display brightness is best toggled for visibility.

### 3.4 Requirement keywords

The key words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, MAY, and OPTIONAL in this document are to be interpreted as described in RFC 2119.

## 4. Color table

The eight colors SHALL be exactly:

| Index | Name     | Hex     | sRGB (R,G,B)     | Binary (RGB) |
|-------|----------|---------|------------------|--------------|
| 0     | Red      | #FF0000 | 255, 0, 0        | 100          |
| 1     | Green    | #00FF00 | 0, 255, 0        | 010          |
| 2     | Blue     | #0000FF | 0, 0, 255        | 001          |
| 3     | Cyan     | #00FFFF | 0, 255, 255      | 011          |
| 4     | Magenta  | #FF00FF | 255, 0, 255      | 101          |
| 5     | Yellow   | #FFFF00 | 255, 255, 0      | 110          |
| 6     | Black    | #000000 | 0, 0, 0          | 000          |
| 7     | White    | #FFFFFF | 255, 255, 255    | 111          |

1. No other colors are permitted within a conforming DOGE implementation.
2. Implementations SHALL NOT support alpha channels or different shades as additional palette colors.

### 4.1 Alpha channel handling

1. When source data contains an alpha channel, the alpha component SHALL be discarded before quantization.
2. Fully transparent pixels (alpha = 0) SHALL be treated as black.
3. Premultiplied alpha data SHALL be converted to straight RGB by the implementation before the alpha is discarded.
4. No other alpha behavior is defined or permitted.

This specification addresses the physical characteristics of emissive display hardware rather than internal software implementation details.

## 5. Mapping to ECMA-48 SGR parameters

Implementations that interoperate with ECMA-48 / ANSI terminals SHOULD map the DOGE colors as follows:

| DOGE Color | SGR Foreground | SGR Background | Bright FG | Bright BG |
|------------|----------------|----------------|-----------|-----------|
| Red        | 31             | 41             | 91        | 101       |
| Green      | 32             | 42             | 92        | 102       |
| Blue       | 34             | 44             | 94        | 104       |
| Cyan       | 36             | 46             | 96        | 106       |
| Magenta    | 35             | 45             | 95        | 105       |
| Yellow     | 33             | 43             | 93        | 103       |
| Black      | 30             | 40             | 90        | 100       |
| White      | 37             | 47             | 97        | 107       |

1. Because the DOGE values are already pure, the "normal" and "bright" slots MAY both be assigned the same pure value.
2. The ordering of the color table and this map matches the preferred DOGE ordering and is not required to match the original ECMA-48 ordering of named colors.

## 6. Quantization (conversion of arbitrary color data)

Two methods are defined for converting continuous or higher bit depth color data into the DOGE palette. A conforming implementation that performs quantization of external color data SHALL use either Clause 6.1 or Clause 6.2.

### 6.1 Hard threshold

For each 8 bit channel independently:

1. If value is greater than or equal to 128, the result SHALL be 255.
2. Otherwise the result SHALL be 0.

This is the direct electronic realization of 1 bit per channel RGB.

### 6.2 Floyd-Steinberg error diffusion

Nearest color selection among the eight DOGE colors, followed by Floyd-Steinberg error diffusion. This method preserves more perceived detail while remaining strictly within the eight pure colors.

#### 6.2.1 Algorithm selection reasoning (informative)

Floyd-Steinberg error diffusion was selected because it is deterministic, preserves structure and edges, and remains strictly within the specified eight pure colors. Gaussian dithering instead introduces random noise drawn from a normal distribution prior to quantization. The result is more stochastic and may reduce patterned artifacts, yet it appears grainier and less sharp.

The existing design principles emphasize intentional minimalism, high contrast, pure channel values, and a clean two method structure. Adding Gaussian dithering would increase complexity without advancing the primary aims of the palette. Hard threshold remains the simple electronic baseline. Floyd-Steinberg already addresses the case of greater perceived detail.

### 6.3 Value handling

1. Input values SHALL be clamped to the closed interval [0, 255] before either quantization method is applied.
2. Floating point or normalized values in the range [0.0, 1.0] SHALL first be scaled by 255 and then clamped.
3. Values outside these ranges after scaling are undefined and SHALL be rejected or clamped at the discretion of the implementer, provided the result remains within the eight specified DOGE colors.

## 7. Design principles

1. Black (#000000) SHALL turn emissive pixels fully off.
2. Each pure primary lights only a single subpixel channel. Each secondary lights exactly two. White lights all three.
3. High contrast is mandatory. Soft midtones are outside the scope of this specification.
4. The palette is intentionally minimal. Any color not listed in Clause 4 is nonconforming.

## 8. Conformance

An implementation is DOGE conformant if and only if:

1. All colors used are exactly those listed in Clause 4.
2. Quantization of external color data, when performed, follows either Clause 6.1 or Clause 6.2.

Optional semantic roles (for example error = red, success = green) MAY be defined by applications but are not required by this specification.
